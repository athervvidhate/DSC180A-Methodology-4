### What is the most interesting topic covered in your domain this quarter?
a. The most interesting topic for me was whether a model responds to how politely you talk to it, and what that actually looks like when you measure it. Going in, we kind of expected rude prompts to make the agents worse. What surprised me was that the pass rates basically did not move, and the agents’ final replies stayed neutral even when the prompt had profanity in it. Both of us rated all 36 replies in the pilot as neutral in tone. The differences we did see showed up in behavior instead. In our open-ended tasks, impolite prompts led to a lot more self-testing (Codex ran 23 test commands across its impolite runs versus 8 for the others). I also learned that measuring any of this is hard when benchmarks are saturated or the problems are already in the training data.

### Describe a potential investigation you would like to pursue for your Quarter 2 Project.
b. For Quarter 2 I would like to run small open-source code models, something in the 7B to 14B range through Ollama or vLLM, inside our own minimal agent loop. The main reason is that every model we tried on the coding problems this quarter solved almost all of them, even Haiku and low-effort settings, so correctness had no room to change. A small model should land somewhere around a 30 to 70 percent pass rate, which means tone could actually move the number if it matters at all. Writing the loop ourselves also lets us fix the seeds and sampling settings and get exact token counts, which we could not do with the subscription tools. I would pair this with fresh AtCoder problems from after the models’ training cutoffs, with our own tests. If there is time, I would try an agentic benchmark like Terminal-Bench too.
### What is a potential change you’d make to the approach taken in your current Quarter 1 Project?
c. The biggest change would be controlling the prompt wording so that only the tone differs. In Study 3 the impolite prompt said “You may write and run your own checks, God knows you need them,” and the other tones did not have that clause. So the extra self-testing we saw might come from the instruction and not from the rudeness, and we cannot separate the two with the data we have. Next time every tone would get the same clause, and we would add a separate arm that tests the line itself. I would also run 2 to 3 repeats per cell. With one run per cell, a result like 17 test commands versus 4 or 5 is hard to trust much. We also spent a lot of time on tasks that turned out too easy, so I would calibrate the difficulty before committing to a design.
### What other techniques would you be interested in using in your project?
d. I would like to finish the LLM-as-judge part and actually run it on real outputs. We built a Gemini checklist judge, a Prometheus 2 rubric judge and a Skywork reward model, but have not yet checked them against our own ratings. Computing Cohen’s kappa and Krippendorff’s alpha against the two human raters would tell us whether a judge can be trusted at all. The other thing is moving past descriptive counts. Right now we only report counts with denominators and compare within each agent, partly because we have one run per cell. With repeats, I think a mixed-effects or regression model with task as a random effect would let us say something real about tone and depth. I would also be curious to read the agents’ reasoning traces to see how they talk about the prompt.
